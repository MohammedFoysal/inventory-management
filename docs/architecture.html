System Architecture

Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talking to a stateless FastAPI service that reads mock inventory, order, and spending data from JSON files. No database, no auth backend — everything lives in process memory.

Tech Stack

Three layers, no database.

Frontend

Vue 3 SPA

localhost:3000 · Vite dev server
  • Vue 3 (Composition API)
  • Vue Router 4 (client-side routing)
  • Axios (HTTP client)
  • Vite (dev server + build)
Backend

FastAPI Service

localhost:8001 · Uvicorn
  • Python FastAPI
  • Pydantic response models
  • In-process filtering logic
  • CORS enabled for local dev
Data

Mock JSON Data

server/data/*.json
  • Loaded once into memory at startup
  • No database, no persistence layer
  • Inventory, orders, demand, backlog, spending

Data Flow: Filters to Rendered UI

How a filter change on the Dashboard reaches the API and comes back as rendered charts.

1

User changes a filter

Time Period, Warehouse, Category, or Order Status selection updates shared refs in useFilters.js (singleton composable state).

2

View requests data

A watcher or method in the view (e.g. Dashboard.vue) calls getCurrentFilters() and passes the result to a function in api.js.

3

Axios issues an HTTP request

api.js builds a query string (warehouse, category, status, month) and sends a GET to http://localhost:8001/api/....

4

FastAPI filters in-memory data

apply_filters() and filter_by_month() in main.py narrow the in-memory lists loaded by mock_data.py.

5

Pydantic validates the response

Filtered results are coerced into response models (InventoryItem, Order, etc.) before being serialized to JSON.

6

Vue stores raw data in refs

The response lands in a raw ref (e.g. allOrders, inventoryItems) inside the view's setup().

7

Computed properties derive UI state

Chart data, totals, and table rows are derived from the raw refs via computed(), so they recalculate automatically and stay cached between renders.
